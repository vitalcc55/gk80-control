# Проверки качества

Текущий уровень охватывает React-прототип, подготовленные состояния и Windows desktop с отдельным core: защищённое соединение, демонстрационное испытание, симулятор и SQLite. Проверки окна, процессного обмена и браузерных подготовленных состояний подтверждают разные свойства; фактические результаты и ограничения приведены в [журнале проверок](first-core-demo-verification.md).

## Подготовка

В Windows подключите проектные инструменты из `development-environment.md`, затем установите зависимости командой `npm ci`. Установка и скачивание браузера выполняются отдельно от проверок. По умолчанию тесты ищут Chromium в `.cache/playwright`. Для установки в этот каталог в PowerShell выполните:

```powershell
$env:PLAYWRIGHT_BROWSERS_PATH = Join-Path (Get-Location) '.cache/playwright'
npx playwright install chromium
```

Если `PLAYWRIGHT_BROWSERS_PATH` задан заранее, установщик и тесты должны использовать одно и то же значение; в таком случае сохраняйте его вместо настройки по умолчанию.

## Команды

- `npm run check:quick` — проверка типов всех исходников, тестов и конфигурации, Biome и Vitest. Используйте во время разработки.
- `npm run check:pr` — быстрые проверки, сборка и Playwright smoke на 1366×768 и 1920×1080. Используйте перед передачей изменений; сервер smoke запускается на `127.0.0.1:5174` и завершается тестовым процессом.
- `npm run ui:fixtures` — просмотр подготовленных состояний на `127.0.0.1:5173`; он не проверяет работу core или оборудования.
- `npm run contract:generate` — явно пересоздать Go DTO и привязки Wails из `api/core.yaml`; `npm run contract:check` — сравнить результат генерации во временной копии с сохранёнными файлами, не изменяя их. Обе команды требуют проектные Go и Wails 3.0.0 из `use-dev-tools.ps1`.
- `npm run contract:test` — проверить, что изменение схемы отражается в Go и TypeScript за один запуск генератора. `go test ./internal/contract ./internal/desktop` проверяет схемы и предметную границу, включая процессный тест владельца; это не заменяет проверку настоящего окна Wails/WebView2.
- `go test ./internal/profile ./internal/transport ./internal/core ./cmd/gk80-core` — проверки профиля, авторизации, обмена с отдельным core, команд, потока событий и истории. Они не проверяют само окно Wails и не доказывают все итоговые сценарии.
- `go test ./internal/storage` — проверить SQLite на временных профилях: миграцию, создание и повторное открытие, атомарность состояния и аудита, пакеты отсчётов, повторы команд, отказ записи и восстановление незавершённой записи. Тесты этого пакета не заменяют отдельные проверки API, симулятора и остановки.
- `.\scripts\build-desktop.ps1` — собрать React и оба Windows-приложения в `bin`; запускать после подключения проектных инструментов. Для сборки окна нужны его статические ресурсы, поэтому desktop entry включается отдельным тегом только при этой сборке. Профиль по умолчанию находится в `%LOCALAPPDATA%\GK80\demo-gk80-control`; `GK80_DEMO_PROFILE_DIR` позволяет выбрать абсолютный путь отдельного demo-профиля.

Обе команды завершаются ненулевым кодом при ошибке; Biome также считает предупреждения ошибками. Проверки не изменяют исходники и lock-файл. Сборка и браузерные отчёты попадают в игнорируемые каталоги. Проверка в IAB и аннотации выполняются отдельно от Chromium smoke.

29 октября 2026 года во временных файлах внутри области проверки подтверждено обнаружение ошибки типа, `any`, `!`, необработанного промиса из другого модуля, некорректного async callback, предупреждения Biome и падающего теста. Файлы примеров удалены. Включённые правила проверяются наряду со строгим TypeScript, но не заменяют проверку поведения программы.

## Дальнейшие этапы

При расширении Go и контрактов добавляйте соответствующие проверки, не создавая фиктивно успешных заглушек. Отдельные race-проверки уже проводились в Ubuntu/WSL; их область и ограничения перечислены в журнале. Полный согласованный race-профиль, coverage, fuzz и проверка зависимостей рассматриваются отдельно. Настройка действий Codex App и запуск Windows-приложения подтверждаются отдельно.
