# Режимы запуска ГК80

Windows-приложение и встроенный браузер Codex (IAB) используют общие экраны, отдельный процесс Go Core и симулятор. Core владеет испытанием, допуском к командам и SQLite.

| Запуск | Назначение | Профиль Windows |
|---|---|---|
| `bin/gk80-desktop.exe` | Штатное приложение ГК80. Собирается через `scripts/build-desktop.ps1` и запускает соседний `gk80-core.exe` | `%LOCALAPPDATA%\GK80\demo-gk80-control\manual-parameters` или абсолютный `GK80_DEMO_PROFILE_DIR` |
| `npm run iab:preview` | Разработка, аннотации и основная ручная функциональная приёмка. Действие Codex «Запустить интерфейс ГК80» запускает этот режим. Адрес `http://127.0.0.1:17880/` | Отдельный постоянный `%LOCALAPPDATA%\GK80\demo-gk80-control\iab-preview`, независимо от настроенного каталога EXE |
| `npm run iab:demo` | Явный запуск IAB для открытия общей истории EXE. Адрес `http://127.0.0.1:17880/demo` | Тот же каталог по умолчанию и та же переменная `GK80_DEMO_PROFILE_DIR`, что у EXE |

В каждом профиле Core хранит историю в `demo.sqlite`. Повторные запуски сохраняют данные. Если preview и профиль EXE указывают на один каталог или общие файлы базы, запуск preview отклоняется. Для проверочной общей истории можно задать отдельный абсолютный `GK80_DEMO_PROFILE_DIR` одинаково у EXE и `iab:demo`.

## Работа в IAB

Подготовьте [окружение разработки](development-environment.md), запустите команду и откройте адрес, напечатанный после готовности Core. Подключение автоматическое. Браузерный хост доступен только локально, обслуживает один активный канал и занимает один порт для обоих режимов. Каждый запуск обслуживает свою страницу, HTTP API и WebSocket. При смене режима ранее открытая вкладка продолжает обращаться к своему адресу.

У общего профиля в каждый момент один Core и один управляющий интерфейс. Перед переключением между EXE и `iab:demo` завершите проход или подтвердите STOP и штатно закройте текущий запуск. Параллельный просмотр активной сессии EXE из IAB запрещён.

Обновление или закрытие вкладки оставляет хост запущенным. При возврате IAB восстанавливает наблюдение без повторной отправки Start. При длительной потере управления Core применяет действующие правила прерывания на симуляторе. Для завершения самого хоста введите `exit` в консоли запуска. Выход процессов и подтверждение STOP проверяются отдельно.

Подготовленные состояния подаются в общие компоненты в автотестах. Ручной проход и аннотации выполняются в `iab:preview`. Порядок приёмки IAB и точной Windows-сборки приведён в [проверках качества](quality-workflow.md#ручная-приёмка).
