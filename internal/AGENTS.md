# Go: границы и исполнение

Правила относятся к `internal` и применяются также к использующим эти пакеты entry points в `cmd`. Для затронутого пакета прочитайте его локальный `AGENTS.md`; wire-контракт регулирует [api/AGENTS.md](../api/AGENTS.md).

## Разделение системы

- Core собирается и работает независимо от React/Wails. HTTP/JSON и WebSocket доставляют предметные команды и наблюдения; обработчик транспорта не реализует методику испытания. Пользуйтесь [system-overview](../docs/engineering/system-overview.md) для границ и [core-contract](../docs/engineering/core-contract.md) для обмена.
- Core — единственный владелец SQLite и активного испытания данного профиля. `uiLeases` связывает внешнюю lease с периодом управления `Engine.Controller`; Controller проверяет действительность этого периода при исполнении. Host поддерживает и наблюдает право, не выдаёт его самостоятельно. Проверяйте допуск у операции, а не только при соединении.
- UI-адаптеры используют один прикладной host. Нативная регистрация Wails изолирована от переносимой логики; не создавайте отдельную Linux-копию Service, ledger или алгоритма для прохождения тестов.
- Core слушает `127.0.0.1`; HTTP и WebSocket защищены случайным секретом между нативными процессами. Секрет не попадает в frontend, URL, аргументы процесса и журналы. Не предоставляйте универсальный прокси вместо разрешённых предметных операций.
- Browser host остаётся локальным demo-инструментом с одним origin и без отдельной браузерной авторизации, вне desktop-поставки. Host/Origin и привязка к каналу не аутентифицируют другие локальные процессы. Разрешён один активный штатный UI: IAB или desktop. Не расширяйте сетевую экспозицию как побочный эффект UI-задачи.

## Конкурентность и ошибки

- У ресурса должен быть один владелец завершения. Отмена контекста прекращает ожидание/работу в предусмотренной границе, но не доказывает, что внешний вызов завершился или оборудование остановилось.
- Перед применением запоздавшего результата проверяйте актуальность относящейся к нему идентичности: процесс/backend, база, сессия, поколение или попытка. Выбор ключей зависит от операции; не вводите один универсальный флаг «актуально» для разных ресурсов.
- Делайте порядок блокировок и владение изменяемыми полями явными. Не добавляйте второй mutex вокруг того же состояния или медленный внешний I/O под блокировкой, необходимой остановке. Переход от синхронного demo-порта к реальному I/O требует отдельного анализа исполнения и отмены.
- Очереди и физически незавершённые вызовы должны иметь обоснованный предел. Истечение ожидания само по себе не освобождает слот реально зависшего вызова. Coalescing наблюдений не является полным журналом событий.
- Ошибки выражают различимые исходы. Подтверждённый отказ, неизвестный результат, отказ SQLite и отказ диагностического writer не взаимозаменяемы. Не маскируйте отказ значением по умолчанию или успешным пропуском.

## Проверки

Для чистой логики используйте содержательные тесты пакета; для владения процессом/обмена — существующие проверки с отдельным core и временным demo-профилем. Синхронизацию проверяйте применимым race-профилем. Нативные bindings и окно имеют отдельные Windows-проверки; [host-checks](../docs/engineering/host-checks.md) описывает их область. Не считайте race родительского host проверкой дочернего core без соответствующей инструментированной сборки.

## Code Review Rules

- Отмечайте алгоритм испытания в транспортном handler, прямой доступ host к SQLite и право управления, выданное обходя core.
- Отмечайте запуск/завершение чужого процесса, фоновые goroutine без владельца и применение результата после смены его идентичности.
- Проверяйте, что упрощение конкурентности сохраняет отдельный путь остановки и не превращает отмену ожидания в ложное подтверждение исполнения.
