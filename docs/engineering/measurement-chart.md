# Жизненный цикл графика измерений

Изменение по #19 / A07 выполнено от `a53d7b0cc6da703793f23e9d289501010c8b380b` после PR #30. Проверенная ревизия программы и тестов — `58e9af7bb555aa794f0a039fc9d7c8e12f3a68ae`, uPlot остаётся закреплённой версии 1.6.32. Отчёт: 4 ноября 2026 года.

## Граница ответственности

Раньше изменение `points`, `target`, `tolerance` или `rangeSeconds` вызывало cleanup и повторное создание uPlot вместе с ResizeObserver и обработчиком загрузки шрифтов. Теперь после React commit отдельно выполняются:

- создание одного экземпляра и его ресурсов на mount;
- подготовка согласованной проекции текущих данных, коэффициентов и диапазона, затем `batch` с `setData`, заданным x и `redraw(false, true)`;
- изменение размера через `setSize`;
- освобождение экземпляра, observer либо fallback resize-listener и font-listener на unmount.

Все текущие числовые props обновляются без пересоздания. Структурных причин пересоздания среди них нет; unmount/remount и начальный проверочный цикл StrictMode создают новый экземпляр. Callbacks осей читают последнюю зафиксированную проекцию. Данные, target, допуск и физические подписи используют одинаковые коэффициенты. Таблица продолжает читать исходные физические значения.

`setData` оставлен со штатным сбросом шкал и курсора: иначе наведённый маркер мог остаться на отсчёте, заменённом на null без изменения границ. Динамический `x.range` сохраняет заданный интервал также при double-click. Внутри batch `redraw(false, true)` пересчитывает оси, не подменяя ожидающий новый x прежними границами. Загрузка шрифтов вне batch вызывает обычный `redraw(true, true)`.

При пустых данных без заданного интервала скрывается только root uPlot: публичный API сохраняет прежнюю auto-x, тогда как новый пустой экземпляр осей не рисовал. Контейнер, экземпляр и таблица сохраняются, последующие данные снова показывают график. Собственные поздние resize/font callbacks после cleanup не обращаются к уничтоженному экземпляру.

LiveRun, его предел 300 точек, отбор sequence, признаки качества, разрывы при потере наблюдения и переводе часов не изменены. Координаторы, частота измерений, core, хранение и зависимости также не менялись.

Счётчики lifecycle дополнительно выведены командой `npm test -- tests/measurement-chart.test.tsx --disableConsoleIntercept` (5 тестов прошли); этот параметр меняет только перехват вывода тестового процесса.

Прежние canvas-сценарии `prototype.spec.ts` сохранены. Новый test-only вход `tests/e2e/chart.html` использует настоящий компонент и настоящий uPlot, не входит в desktop/browser entry. Он проверяет на одном canvas переходы между обычным, малым (`1e-100`), большим давлением (`1e200`), узким размахом около `1e-15`, временем до `1e307`, пустым и автоматическим диапазоном. Есть переходы с одинаковыми нормализованными числами, но новыми коэффициентами давления и времени (`1e-100 → 2e-100`).

Проверяются реально нарисованные конечные и различимые подписи, исходная таблица, вызовы настоящего canvas stroke для target, перепада и двух границ допуска, цветные пиксели сегмента давления и их отсутствие на null-разрыве. Отдельно проверены double-click, скрытие наведённого маркера на разрыве, resize и сохранение того же canvas. Выигрыш FPS и потребления памяти не измерялся и не заявляется.

## Настоящие Windows/WebView2 и IAB

Использован отдельный demo-профиль, последовательно Windows и `npm run iab:demo`, с настоящими host, core, симулятором и SQLite. Исполняемый код при этих запусках совпадает с проверенной ревизией; второй коммит меняет только тесты.

| Поверхность | Фактический результат |
|---|---|
| Windows/WebView2 | Испытание `3672fcdd-0260-4e3d-95fd-9514d304e5d8`, 10000 Па / 60 с. Видны поступающие ДД1 и перепад, обе оси, target и таблица физических значений. Выполнены maximize/restore. После паузы своего core показано неподтверждённое состояние; после восстановления таблица содержит `33,7495 / Нет данных / Нет данных` и новые отсчёты с `39,485`. Естественное завершение: «Завершено / Полные / Сохранено», запись повторно открыта с измерениями и аудитом |
| Живой IAB | Испытание `600d8258-6c6d-488a-a91c-388c299bf51e`, 10000 Па / 120 с. Поступление обоих каналов, target и таблица проверены. При resize ширина canvas изменилась с 590 до 832 CSS/внутренних пикселей; временный viewport сброшен. После паузы виден разрыв обоих рядов, таблица содержит `40,1885 / Нет данных / Нет данных`, затем новые отсчёты. Stop подтверждён core: «Прервано / Неполные / Сохранено»; результат повторно открыт |

Разрыв проверялся существующим диагностическим средством: свой процесс core приостанавливался на 10 секунд с автоматическим возобновлением. Это реальная пауза процесса, а не подмена графика; она не доказывает отказ физической сети, датчика или SQLite. В Windows подтверждены предупреждение, пропуск в таблице и поступление новых отсчётов; отдельный кадр геометрии разрыва после восстановления там не сохранён. В IAB геометрия разрыва просмотрена на canvas. В живом LiveRun нет конфигурации допуска: его линии подтверждены в компонентных и настоящих canvas-проверках с подготовленными данными, не объявляются проверенными в live-режиме.

Оба окна/вкладка закрыты, управление Computer Use освобождено. Собственные desktop/browser и core отсутствуют в процессах; журналы подтверждают `process.stopped`, для обоих core host записал код выхода 0. Обёртка `iab:demo` при Ctrl+C завершилась кодом 1 с предупреждением о неподтверждённом выходе и сохранила временный каталог; последующей проверкой подтверждены остановка host/core и штатные записи завершения. Предупреждение не переименовано в успешный выход обёртки.

Локальные артефакты сохранены в `.tmp/.codex/chart-lifecycle/`: красная регрессия, результаты проверок и счётчики, SHA-256 сборки, accessibility-снимки Windows, снимок canvas IAB и таблица восстановления, журналы остановки. Эти игнорируемые файлы не включены в PR и недоступны независимому читателю GitHub.

## Ограничения и отдельные наблюдения

- Полный предслиятельный `verify` и Go test-suite в этой frontend-задаче не запускались. Записанный в main неуспешный verify PR #30 из-за Windows/Kaspersky остаётся неуспешным; исключение для нового PR не предполагается. Защита, имена бинарников и параметры компиляции ради обхода не менялись. Текущие frontend-проверки и сборки этим отказом не были заблокированы.
- Пять `ERROR framework.message` в журнале настоящего desktop остаются неклассифицированными. Это поверхность #21, не подтверждённая регрессия графика и не доказанно безвредное сообщение; расследование не перенесено в #19.
- Нативный Windows remount незавершённой команды не перепроверялся и не считается исправленным этим изменением. Общая приёмка #6/#7 и физическое оборудование не входят в данный результат.

Независимые read-only review реализации и числовых переходов завершены без оставшихся подтверждённых замечаний. Две найденные при первом review регрессии (double-click диапазона и курсор на null) воспроизведены на настоящем canvas и исправлены до первого коммита.
