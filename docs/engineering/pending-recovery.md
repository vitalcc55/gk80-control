# Восстановление наблюдений команд

Список принадлежит конкретной `databaseId`. При возврате компонента после отказа записи он согласует память с актуальным Storage; восстановление не отправляет команды повторно. Снятие блокировки новых обычных команд требует успешной записи согласованного списка. Stop отправляется отдельным путём с существующими ограничениями.

| Ситуация | Правило |
|---|---|
| Точное совпадение | `id`, вид, испытание, действие и исходная строка JSON совпадают; доступное подтверждение из памяти сохраняется за этой попыткой. |
| Одинаковый `id`, но другое содержимое | Записи остаются отдельными; результат одной не переносится на другую. |
| Разные базы | Память и Storage разделены по `databaseId`. |
| Прежняя запись без JSON | Сохраняется как непроверяемая; точная сверка без исходного содержимого не выполняется. |
| Ошибка чтения или записи | Неизвестность сохраняется, обычные команды блокируются; известные попытки остаются видимыми. |
| Более 65 записей после объединения | Записи не обрезаются; сохранение и обычные команды блокируются до уменьшения списка. Stop остаётся доступной в пределах существующих ограничений. |
| Прекращение наблюдения | Удаляется только выбранная точная запись; действие подтверждается успешной записью. При ошибке запись остаётся видимой. |

Для повторной активации Stop в локальной записи создаётся новая версия наблюдения. Она позволяет отличить обновление другой вкладки от старого снимка; версия не входит в идентичность команды и не отправляется ядру. Старые записи без версии остаются допустимыми.

Storage не сохраняет статус ответа команды. Подтверждение в памяти переживает перемонтирование компонента, но после полной перезагрузки страницы нужна повторная точная сверка.
