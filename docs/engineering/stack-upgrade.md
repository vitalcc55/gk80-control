# Согласованное обновление стека

## Результат и исходная точка

Обновить согласованные зависимости, воспроизводимо получить типы и собрать
desktop/browser с прежним поведением команд, хранения и восстановления.
Приёмка включает существующие автоматические проверки Windows/Linux и отдельные
проходы настоящего Windows/WebView2 и IAB. Наличие совместимых peer-диапазонов
само по себе не подтверждает этот результат.

Исходный `main`: `e0ffb9d4e28b984514774554cdf237dcda47d0c4`, после PR #33.
Локальная основа миграции дополнительно содержит принятое обновление Medeo Sans
`4407ffa`; шрифт сохраняется. Последний полный verify PR #33 относится к прежнему
стеку и не выдаётся за проверку обновлённых зависимостей.

## Границы и сохраняемые решения

- React → тонкий Wails-адаптер → локальные HTTP/JSON и WebSocket → отдельный Go
  core → симулятор/SQLite; предметные правила не переносятся между слоями.
- Node 24.22.2, npm 11.19.1, Go 1.27.3, TypeScript 7.0.2, React 19.3.1,
  jsdom 30.1.3, Playwright 1.64.1 и остальные невыбранные прямые пакеты сохраняются.
- OpenAPI 3.1.2, JSON Schema 2020-12 и YAML v3 сохраняются. Схема БД, точные
  исходные команды, идемпотентность, Stop, lease, сроки и аудит не меняются.
- `modernc.org/libc` остаётся 1.79.0; косвенные библиотеки обновляются только
  по требованиям выбранных владельцев. Независимого повышения kin-openapi нет.
- Строгость типов, правила lint, проверки generated и критерии приёмки
  не ослабляются. Исторические отчёты и разовые исключения остаются историческими.
- Новые функции, внедрение Zustand, переделка UI, реальные устройства, упаковка,
  новый build framework и исправление U01 не входят в миграцию.
- Существенная несовместимость, требующая изменения этих контрактов, — условие
  остановки для отдельного решения. Защита Windows не изменяется и не обходится.

## Подтверждения

- Frontend: `check:quick`, затем итоговый `check:pr`; все три входа сборки,
  существующие проверки графика, шрифта и пяти экранов. Чистая установка из lock.
- Go: существующие contract/storage/demo/core/transport/browser тесты, включая
  rollback/audit/context/reopen, vet/lint и согласованность модулей. Это не отдельное
  доказательство каждой новой внутренней ветви стороннего SQLite-драйвера.
- Генерация: `contract:generate`, `contract:check`, `contract:test`; 14 файлов,
  два сервиса, 24 метода, три события, обязательные поля и отсутствие `any`.
- Host: portable/native, отрицательные runner-сценарии и отдельный корневой
  `go test -tags=desktopapp .`. Native-профиль desktop не заменяет корневой тест.
- Linux: отдельная установка/сборка frontend и portable host с race в Ubuntu/WSL;
  GUI не требуется. Инструментация дочернего core указывается отдельно.
- Windows/WebView2: холодный запуск, Create/Start/Confirm, показания, Stop,
  сохранение, закрытие, повторное открытие. Доставка через fallback сама по себе
  не доказывает конкретное Wails-событие.
- IAB: настоящий demo-core/SQLite, refresh без повторных команд, потеря core,
  достоверность состояния и завершение собственных процессов. Fixtures отдельно.
- Старая история: копия закрытого существующего demo-профиля; чтение завершённых
  и прерванных записей. Оригиналы не изменяются и не используются для новых опытов.

## Фактические результаты

До установки нового дерева: Windows 11 x64, Node 24.22.2/npm 11.19.1,
Go 1.27.3, Wails 3.0.0, golangci-lint 2.15.0. Ubuntu/WSL:
Linux 6.6.87.2, Node 24.22.2/npm 11.19.1, Go 1.27.3, GCC 13.3.
Эти сведения относятся к исходному окружению; проверки обновлённых частей ниже.

### Frontend

Семь выбранных прямых пакетов установлены штатным `npm install` без `--force`,
`--legacy-peer-deps` и изменения npm/Node. Прочие прямые версии, в том числе
Wails runtime 3.0.0 и jsdom 30.1.3, сохранены. В lock-файле 264 записи вместо 272:
изменились 84 пути, включая платформенные варианты и устранение вложенных копий
Lightning CSS/magic-string. Изменения соответствуют владельцам Vite, Tailwind,
Vitest и Biome; отдельного обновления косвенных пакетов не выполнялось.

Windows `npm run check:quick` прошёл: строгая проверка типов, Biome без
предупреждений и 522 теста в 16 файлах на Vitest 5.1.0. Рукописные компоненты,
тесты и их ожидания не менялись. Два независимых read-only review не обнаружили
конкретных замечаний. После review прошли `check:pr` (522 Vitest и 37 Playwright,
типы/lint/fixture-сборка), `build:desktop` и `build:browser`. Последние две команды
здесь подтверждают frontend-входы, не сборку/запуск нативной оболочки. Чистая
установка окончательного lock и Windows/Linux/IAB на этом шаге были оставлены
для итоговой проверки, результаты которой приведены ниже.

### Go и генератор

Адресный `go get` изменил ровно пять выбранных версий; `go mod tidy` удалил старые
контрольные суммы этих версий. `go mod tidy -diff` после этого чист, `go mod verify`
прошёл. Фактический выбранный граф сохраняет libc 1.79.0, kin-openapi 0.142.0,
Go 1.27.3 и пока Wails 3.0.0.

Штатная генерация Wails 3.0.0/oapi-codegen 2.8.2 выдала 14 файлов; единственная
дельта generated — версия oapi-codegen в заголовке `models.gen.go`. `contract:check`
и `contract:test` прошли без ослабления условий. OpenAPI, поля DTO, TypeScript,
сервисы, методы и события не менялись.

На Windows прошли полные существующие тесты пакетов contract, storage, demo,
core, transport, browser и desktop с `-count=1 -timeout=240s`, а также vet/lint
этих пакетов. Рукописный Go-код и тесты не менялись. Проверки включают реальные
временные SQLite, rollback/audit/reopen и отдельные core-процессы; не заявляется
прямое покрытие каждой новой внутренней ветви драйвера. Два независимых read-only
review этой части не обнаружили конкретных замечаний; старую историю на этом
шаге оставили для отдельной проверки через обновлённое приложение.

### Wails

CLI установлен в выделенный каталог `%LOCALAPPDATA%/gk80-control/go/bin`;
реально вызываемый CLI, выбранный Go-модуль и установленный frontend runtime
имеют версию 3.1.0. Node/npm/Go и системный PATH не обновлялись.

Это результат графа владельца, не отдельная миграция этих библиотек;
libc/kin-openapi/x/sys сохранены.

Строгая проверка CLI теперь требует 3.1.0. Генерация сохранила все условия

В действующих инструкциях изменена версия Wails; датированные результаты старых
опытов с 3.0.0 сохранены. Типизированная классификация FatalError и порядок

На Windows прошли portable и native host-профили, отдельный полный корневой

После review прошли нативная сборка `scripts/build-desktop.ps1` и browser-сборка.
Окончательную чистую установку, полный набор и реальные Windows/Linux/IAB-проходы
на этом шаге оставили для итоговой проверки ниже.

### Наблюдаемое поведение Windows и IAB

Полный оконный проход и старая история сначала проверены сборкой непосредственно
перед коммитом Wails: её build info содержит `d45e471` и `vcs.modified=true`.
Это уже обновлённые код/зависимости, позднее зафиксированные в `5d37cc6`;
прикладные исходники между сборкой и коммитом не менялись. После полного verify
дополнительно запущены его desktop/core с build info `5d37cc6`,
`vcs.modified=false`; контрольные суммы сохранены в final-native-launch.json.
Этой чистой сборкой повторно открыта Windows-запись и прочитана запись после
аварии IAB-core: finished / unknown / incomplete / saved. Интерфейс показывает
«Не подтверждено», «Неполные», «Сохранено»; автоматического продолжения нет.
Затем оба процесса штатно закрыты с core.stopped(exit=0).

В настоящем Windows/WebView2 собранная оболочка прошла холодный запуск,
Create → Start → Confirm, обновление показаний симулятора, Stop и получение
подтверждения ядра. Сохранён результат `d0e249a1-f96e-4565-b2a0-60e59249bc26`:
прервано / неполные данные / сохранено. После закрытия и повторного запуска
он открылся с параметрами и исходными измерениями. При обоих штатных закрытиях
диагностика содержит process.stopped для desktop/core и core.stopped(exit=0);
принадлежащие им PID завершены. Показания в окне подтверждают работу интерфейса,
но не изолируют доставку Wails-событий от существующего fallback.

В оконных опытах зарегистрированы пять `ERROR framework.message`
с `error_code=unclassified`, без operation: три в первом проходе и по одной
при закрытии старой истории и чистой финальной сборки. Это сообщения framework
logger, а не доказанный вызов ErrorHandler. Команды первого прохода получили
подтверждения; оба дополнительных закрытия затем записали core.stopped(exit=0).
В прежнем журнале оконного опыта Wails 3.0 также есть сообщения этого уровня,
но общая причина не установлена. Ни безвредность, ни регрессия этими записями
не доказаны. Дальнейшая классификация остаётся вопросом диагностики (#8),
а не скрытым исправлением в миграции. Полного отсутствия runtime-ошибок
этот проход не подтверждает.

В настоящем IAB через штатный `iab:demo` открыт тот же demo-профиль с историей
Windows. Создано второе испытание и начато измерение. Refresh восстановил
его текущее состояние и показания; по выполненному сравнению **значения всех
8 строк commands до/после совпали**. Это сравнение строк, не байтов всего
SQLite-файла. Из одного равенства БД нельзя исключить идемпотентный повтор
запроса с тем же ID. Дополнительно browser-журнал содержит только три
command.sent до refresh (10:17:55, 10:18:00, 10:18:03 UTC), без новых до потери
core в 10:18:57 UTC. Этот event пишется перед host → core send. В опыте
повторная отправка на этой границе не зарегистрирована; неблокирующий
диагностический журнал не является полной сетевой трассировкой frontend.

Поведение восстановления без повторного вызова изменяющей операции отдельно
проверяют существующие тесты live-flow (browser shared storage, Stop после
remount и Create после неизвестного ответа); они прошли в составе 522 Vitest.
Это автоматические проверки с подменённой границей, не отдельный native remount.

Затем принудительно завершён только core этого запуска: интерфейс показал
«Связь с ядром потеряна» и недоступность истории до подключения. Это намеренный
аварийный опыт на симуляторе. Отдельный сохранённый снимок строк commands после
refresh снят позже, уже после потери core; он также совпадает с исходным набором.

После Ctrl+C обёртка завершилась с кодом **1** и явно сообщила, что корректное
завершение сеанса/ядра не подтверждено. Для принудительно завершённого core
диагностика сохранила exit_code=4294967295; browser записал process.stopped.
Оба принадлежащих этому запуску PID отсутствуют. Эти наблюдения **не доказывают
graceful shutdown** аварийного IAB-сеанса. Поведение обёртки не исправлялось
в рамках обновления зависимостей.

Типизированные ошибки Wails и фильтрация диагностических полей проверены
существующими корневыми/diagnostics-тестами. Нативный FatalError в окне намеренно
не провоцировался. Ограничение обычного Chromium error callback с последующим
os.Exit, native remount и полный цикл IAB-аннотации остаются прежними границами;
этот проход их не закрывает. Реальное оборудование и общая приёмка приложения
также не подтверждаются.

### Старая история и итог

В отдельную копию закрытого профиля перенесена прежняя demo SQLite с двумя
испытаниями: `3672fcdd-0260-4e3d-95fd-9514d304e5d8` (завершено / полные /
сохранено) и `600d8258-6c6d-488a-a91c-388c299bf51e` (прервано / неполные /
сохранено). Обе записи открыты в обновлённом настоящем Windows/WebView2
с параметрами и исходными измерениями. Новые испытания в этой копии не создавались.

После штатного закрытия все значения строк семи таблиц копии совпали с источником:
tests, measurements, test_actions, commands, audit, meta и sqlite_sequence.
Сохранены 8 команд и 11 записей аудита, `integrity_check` вернул `ok`.
SHA-256 оригинального DB-файла не изменился. Диагностика подтверждает
process.stopped обоих процессов и core.stopped(exit=0); оба PID завершены.

Согласованный объём обновления стека выполнен без изменения рукописной
предметной логики, UI-компонентов, схем, тестов и их ожиданий. Generated изменился
только заголовком версии oapi-codegen. Последний коммит отчёта добавляет
документацию после проверенной ревизии кода и не выдаётся за отдельный новый
прогон. Итоговые read-only review проверяют scope и соответствие утверждений
сохранённым свидетельствам; выявленная неполнота описания framework-ошибок
устранена явным ограничением выше. Отчёт не объявляет весь runtime свободным
от ошибок и не закрывает ранее сохранённые функциональные и аппаратные вопросы.

Сырые результаты, графы и изолированные demo-профили:
`.tmp/.codex/stack-upgrade/`. Итоговые результаты и ограничения дополняются
после соответствующих проверок; отсутствие запуска не считается PASS.
